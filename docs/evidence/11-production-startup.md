## C10 — 결과물 주소의 첫 화면은 공개 소개 페이지이고, 등록 없이 열린다

```
요청: GET / (쿠키 없음)
응답 상태: 200
```

첫 화면에는 "패스키 포트폴리오" 제목, 서비스 소개 문구, "나만의 공간으로 이동" 버튼만
있다. 등록/로그인 없이 심사자가 바로 열어볼 수 있다.

## C11 — "1번 과제" 소개 페이지에 이어 붙였는가

**⚠️ 확인 필요 / 정직하게 밝힘**: 이 T08 프로젝트는 별도의 독립 저장소
(`t08-passkey-portfolio`)로 처음부터 새로 만들었다. 이전 과제(1번)의 소개 페이지 코드를
그대로 이어 붙인 것이 아니라, T08 과제 자체를 위한 새 공개 소개 페이지를 작성했다.

- 만약 "1번 과제"가 이 학습 과정에서 별도로 제출한 다른 프로젝트를 가리키는 것이라면,
  이 기준은 **현재 미충족** 상태다 — 두 프로젝트가 물리적으로 이어져 있지 않다.
- 다만 이 프로젝트의 첫 화면 자체는 "공개 소개 페이지 → 이어서 개인 공간으로 이동"이라는
  같은 구조(공개 영역 다음에 인증이 필요한 개인 공간이 오는 구조)를 따르고 있어서, 요구하는
  **패턴**은 지키고 있다.
- 정확히 어떤 것을 "1번 과제"로 간주해야 하는지 과제 발행자에게 확인이 필요하며, 만약
  기존 1번 과제 페이지에 실제로 이어 붙여야 한다면 별도 작업이 필요하다.

## C12 — 실제 개인정보가 없고, 만들어 넣은 데이터라는 사실이 적혀 있다

- 비공개 자료 3건은 전부 `getSyntheticPrivateItems()`가 만들어내는 합성(가짜) 데이터이며,
  제목/본문에 "합성", "가상 데이터입니다"라는 표현을 명시적으로 넣었다.
- 로그인 화면 안내문에도 "합성(가짜) 이름을 적고 패스키를 만들어보세요"라고 명시했다.
- `T08-SUBMISSION.md`의 "짧은 확인 방법"에도 "합성 이름 입력"이라고 명시했다.

이로써 제출물 어디에도 실제 개인정보가 들어가지 않으며, 넣은 내용이 데모용으로
만들어낸 것이라는 점이 코드 문구와 제출문 양쪽에 기록되어 있다.
